# Access to Nuclide: web, API, CLI and MCP

Every record in Nuclide is available four ways from the same build. Nothing is behind a key, and every route carries the same attribution line: `Data from Nuclide, CC BY-NC 4.0; commercial use needs a licence`.

| Route | For | Where |
|---|---|---|
| Web | People | One page per record; Ask Nuclide at `/ask/` |
| Static API | Scripts, spreadsheets, pipelines | `/api/v1/` (JSON, NDJSON, CSV, JSON Schema, Markdown context), documented at `/api/` |
| CLI | Terminals and shell pipelines | `npx nuclide ...` from `packages/nuclide-cli` |
| MCP | Claude, Cursor and other assistants | `npx -y nuclide-mcp` from `packages/nuclide-mcp`; `npm run mcp` in a checkout for the larger repository server |

No domain is registered for this project yet; `SITE` in `src/lib/seo.ts` is a placeholder, and every route above is relative to wherever the site is deployed.

## The static API

`scripts/build-api.ts`, `scripts/embed.ts`, `scripts/build-ask.ts` and `scripts/build-context.ts` write `public/api/v1/` at build time; Vercel serves it with permissive CORS. The files the CLI and MCP server read:

| File | Contents |
|---|---|
| `meta.json` | Build date, version, counts per kind, the file list |
| `<plural>.json`, `<plural>.csv` | Every record of one kind (`drugs.json`, `trials.csv`, `key papers.json`) |
| `entities/<id>.json` | One record with its neighbours grouped by kind |
| `search.json` | Compact search documents (id, kind, name, aka, tldr, tags, route, status) |
| `embeddings.json`, `embeddings.bin` | The concept-search index (TF-IDF, sparse unit vectors) |
| `ask-index.json` | Names, aliases and curated question pairs for Ask Nuclide |
| `context/<id>.md` | One Markdown document per record; `context/index.md` lists them |
| `all.json`, `all.ndjson`, `schema.json`, `ranking.json` | Whole-corpus downloads, the entity JSON Schema, the institution ranking |
| `openapi.json` | OpenAPI 3.1 description of every file here and the feeds, generated by `scripts/build-openapi.ts` from the layout in `scripts/api-layout.ts` (shared with `meta.json`) |

Alongside, `scripts/build-context.ts` writes `public/llms.txt` (committed, deterministic) and `public/llms-full.txt` (gitignored, one line per record) for language models. Citation metadata is in `CITATION.cff`; tagged releases attach the whole bundle (see `.github/workflows/release-dataset.yml`).

## CLI: `nuclide`

```sh
npx nuclide search "lutetium-177 PSMA" --kind drug
npx nuclide get pluvicto
npx nuclide list trial --filter status=recruiting --limit 20
npx nuclide ask "What is the half-life of actinium-225?" --region UK
npx nuclide context vision
npx nuclide kinds
npx nuclide export isotope --csv > isotopes.csv
```

`--json` on any command prints machine-readable output and moves the attribution line to stderr. `NUCLIDE_API` or `--api` points at another copy of `/api/v1`, including a local `out/api/v1` directory, which works offline. Full reference: `packages/nuclide-cli/README.md`.

## MCP: `nuclide-mcp`

Tools `search`, `get_entity`, `list_kind`, `ask`, `context` and `compare`; resources `nuclide://kinds` and `nuclide://kinds/{kind}`; prompt `nuclide-brief` (patient or clinician summary). Claude Desktop, Claude Code and Cursor snippets are in `packages/nuclide-mcp/README.md`. The short form:

```sh
claude mcp add nuclide -- npx -y nuclide-mcp
```

The `ask` tool and `nuclide ask` run the site's own pipeline (`src/lib/ask-pipeline.ts` and friends), bundled in at build time, so the three surfaces give the same cited answer for the same question.

## Building and testing the packages

```sh
npm run cli:build        # packages/nuclide-cli/dist/nuclide.mjs (no runtime dependencies)
npm run mcp:build        # packages/nuclide-mcp/dist/nuclide-mcp.mjs (depends on @modelcontextprotocol/sdk and zod)
npm test                 # includes packages/*/src/**/*.test.ts
```

`scripts/build-packages.ts` bundles each package with esbuild from `packages/*/src/bin.ts`; the site's modules are imported by relative path, so there is no copied code to drift. To try either against a local build: `npm run build` (writes `out/api/v1`), then `NUCLIDE_API=./out/api/v1 node packages/nuclide-cli/dist/nuclide.mjs kinds` or `NUCLIDE_API=./out/api/v1 node packages/nuclide-mcp/dist/nuclide-mcp.mjs`.

## Publishing

Each package has its own `package.json` with a `prepublishOnly` step that builds the bundle. From the repository root, after `npm ci`: `npm run cli:build && (cd packages/nuclide-cli && npm publish)` and `npm run mcp:build && (cd packages/nuclide-mcp && npm publish)`. Bump the `version` fields first; the version is injected into `--version` at build time.
